# dsh-myskin (v0.3.9)

**DSH 通用皮肤框架**：可视化自定义 + 实时预览 + 「皮肤管理」设置页，Web 与 Desktop 共用同一套客户端插件管线。

皮肤是一层**完全可逆的覆盖层**：不改 DSH 源码、不动 DSH 进程；关掉开关或点「还原默认」即回到原生外观。

> 适配 **DSH 0.1.7-rc.2**、**0.2.0-rc.1** 与 **0.2.0-rc.2**（Web 与 Desktop）；`npm run check:types` 逐字段对着本机安装的 DSH 校验。

## 这是什么

一句话：**把 DSH 变成你自己的样子，而且随时能变回去。**

- **不侵入**：所有改动都写在插件自己的条目里（皮肤文档 + 一个自有 `<style>`），不碰 DSH 的源码、配置与进程。
- **可逆**：每个字段都能逐项清除，「还原默认」或关掉「启用皮肤」即精确还原。
- **可视化**：内置「绘制模式」画布编辑器——在**真实页面**上点选元素改样式、改文字、换字体、挪位置，边改边看。
- **可搬运**：整套皮肤连同图片、字体打包成 `.dshskin`（类 zip 容器），换机器/换 profile 一键导入。

| 方向 | 这一版做了什么 |
|---|---|
| **回收站** | 「移除控件」拿掉的组件进入绘制模式的**回收站**，可单项/全部恢复（只在绘制模式里出现） |

| **图片锚定** | 嵌入图可锚定 **元素 / 文字 / 内置组件**；拆分为 **组件嵌入**（组件内）与 **组件锚定**（组件外独立图层） |
| **组块编辑** | 面板「编辑范围：仅此元素 / **整组**」——改一次，**同类的每一个**（含之后新建的）一起变；工作区行与对话行按 **ARIA 语义**区分 |
| **整组图片** | 组内嵌图：一张图贴遍**每一条**工作区行，新行自动带上；成员离开组即收回 |
| **整组间隔** | 只调**成员彼此之间**的距离（`A + A { margin-top }`），首成员与容器顶不动 |
| **可诊断失败** | `保存失败：canvas` 现在会说明原因（宿主 schema 比客户端旧 → 重启 DSH；或画布数据过大） |

## 能做什么

### 皮肤管理页（设置 →「皮肤管理」）

| 能力 | 说明 |
|---|---|
| 启用 / 停用 | 一键开关整套皮肤；停用即完全还原 |
| 预设主题 | 深海 / 暖阳 / 粉黛一键换肤（走官方令牌通道）；每套都按对比度底线校验过文字可读性 |
| 实时预览 | 不写入文档也能先看效果 |
| 绘制模式 | 在真实页面上可视化编辑（见下节） |
| 皮肤库 | 保存 / 重命名 / 上移下移 / 复制 / 加载 / 删除多个命名皮肤 |
| 导出 / 导入 | 皮肤包 `.dshskin` |

### 绘制模式（画布编辑器）

进入方式：**设置 →「皮肤管理」→ 绘制模式**。设置弹窗会关闭，真实页面内缩，顶部出现工具条、右侧出现面板——**不是复制一份界面，就在真实页面上改**。

**选中元素**

- **选择**模式：悬停即显示虚线框与标签（`button#go.btn · 发送`），点击选中；**交互**模式：正常使用页面（滚动、点按钮不会误选）。
- 面板顶部 **↑ 父级 / ↓ 子级**（Alt+↑ / Alt+↓）按真实 DOM 一次走一级。
- **编辑范围（组块）**：面板顶部可选 **仅此元素 / 整组**。选「整组」后，每一次改动写的是**同类元素的公共选择器**——
  侧栏里改一次「工作区行」，所有工作区（**包括之后新建的**）一起变；改工作区行里的「…」按钮，只影响各个工作区的「…」，不会波及对话行。
  工作区行（`[role="treeitem"][aria-expanded]`）与对话行（`[role="treeitem"]:not([aria-expanded])`）按 **ARIA 语义**区分，
  不依赖构建期的 class 哈希；面板会显示「将写入」的完整选择器与当前命中数量；识别不出同类组时「整组」按钮不可选，
  不会把"只有一个元素的一组"当成组。整组时还多一个 **间隔** 字段：只调**成员彼此之间**的距离（组选择器 + 组选择器 { margin-top }），
  第一个成员与容器顶的距离不变，之后新建的成员同样适用；成员不是相邻兄弟时该字段不出现并说明原因。
  文字替换**始终只作用于当前元素**（每行名字本来就不同）。
- 快捷键：`Esc` 取消选择（再按退出并保存）、`Ctrl/Cmd+Z` 撤销、`Ctrl/Cmd+Shift+Z` 重做——在输入框里不会抢键。

**改样式**（右侧面板，可折叠）

- 分组：**文字 / 盒子 / 外观 / 位置与缩放 / 元素操作**，标题带「自定义 N」计数。
- 每个已生效的字段都能**单独清除**（×），不用为改一个属性去清空整个元素。
- 字段改动**即时预览**；隐藏控件（保留占位）/ 移除控件（不占位）都是纯 CSS，不删除真实节点。
- **回收站**：被「移除控件（不占位）」拿掉的组件会出现在右侧面板的「回收站」里，可**单项恢复**或**全部恢复**。
  它**只在绘制模式里出现**——回收站属于"正在改皮肤"的那只手，皮肤管理页保持只读。
  恢复只删掉那条 `display: none`，元素上其它自定义原样保留；
  即使这条移除**已经保存进皮肤**，恢复也**立刻可见**——编辑器会量出元素本来该用的 `display`，在自己的预览层里压过已提交的规则，直到下次保存把它彻底带走。
- 值一律走 `--dsw-*` 令牌与真实 CSS，深浅色主题自动跟随。

**位置与缩放**

- **X / Y 位移**、**等比缩放**（带滑块）；数值框上**滚轮微调**（X/Y ±1px、缩放 ±0.05，按住 `Shift` 步长 ×5/×10）。
- 画布上选中框**左上角 ✥ 拖动＝双轴移动**，**右下角手柄拖动＝等比缩放**。
- **每个轴独立重置**（↺），也可以一次「重置变换（三轴）」。
- **对齐线（低敏吸附）**：移动或缩放时，元素与**同级/父级元素的边与中线**、以及**视口中线**在 4px 内会自动吸附，
  并在画布上画出对齐线；磁力很小（4px）且只在已经接近时生效，按住 **Alt** 可临时关闭，工具条「对齐」可整体开关。
- 只做视觉位移/缩放，**不改变布局流**；归零即删除 `transform`，不留 `transform: none`。
- **不抽搐**：拖动期间只有 `transform` 会被改写——元素上的宽高、内边距、字号等自定义一律原样保留，
  不会"丢一帧、再补回来"；面板里的数字是**只读镜像**，绝不会把上一帧的旧坐标写回去。
  同理，编辑器的草稿样式表**始终排在最后**，所以「保存」之后继续拖动，也不会被已提交的旧坐标拽回去。

**文字与字体**

- 「编辑文字」：自动定位真正承载文字的节点（含灰色的默认占位文字），**边输入边预览**，回车或「应用文字」写入草稿。
- 「字体」：可直接填任意字体栈（含系统字体），或用建议列表（PingFang SC / Microsoft YaHei / Noto Sans CJK SC / HarmonyOS Sans / JetBrains Mono …）。
- **本机字体列表**：「本机字体」按钮读取**这台机器上真正装了的字体**并列出（可搜索、点击即应用，每个名字用它自己的字体渲染）。
  Chromium 内核走 Local Font Access API（首次会弹一次授权）；不支持该接口或拒绝授权时，自动退化为**常见字体探测**——
  逐个测量候选字体是否真的存在。列表顶部会写明当前是哪一种来源，不会把两者混为一谈。
- **嵌入字体文件**：`.woff2/.woff/.ttf/.otf`（≤ 30 MB）随皮肤保存；超过 2 MB 会明确提示代价（见下）。
- **整站字体（界面 / 正文 / 代码）**：三行各自填字体栈，互不干扰、可各自清除——
  **界面**＝全局基准（走 DSH 自己的 `--dsw-font-family`，页面各处 `font:` 简写都读它）；
  **正文**＝对话内容与 markdown 的覆盖（不写 `!important`，所以段落里的行内代码仍是代码字体）；
  **代码**＝代码块 / 行内代码 / 代码编辑器（走 `--ds-font-family-code`）。
  每行都有「本机」按钮：从本机字体列表里挑一个写进这一项（会自动补上同类兜底字体，换机器也不至于掉到衬线体）。

**画面**

- **背景图**（壁纸）+ **背景强度**滑块（拖动即时预览、松手自动保存）。
- **嵌入图片**：先选中一个容器，再选图；可拖动、缩放、调不透明度与混合模式。
- **两种呈现方式**（每张图可单独选）：
  **整组锚点**＝在「整组」范围下嵌入（或在锚点下拉里选「整组」），一张图贴到**同类的每一个**元素上——例如每条工作区行各一张，
  **之后新建的工作区也自动带上**；
  **组件嵌入**＝画在**组件内部**（在组件背景之上、内容之下，随组件一起被裁剪——就是原来那种）；
  **组件锚定**＝画在**组件之外**的独立图层上（固定覆盖层、不吃点击、z-index 盖得住应用表面但盖不住对话框），
  可以负偏移露到组件外面，而且**完全不改动该组件自身的定位与裁剪**。
- **锚定**：每张嵌入图都有一个**锚点**，决定它跟着谁走，面板上随时可改：
  **元素**（结构选择器，默认）/ **文字**（跟着这段文案——选中那行字点「取选中文字」即可）/ **内置组件**（整个应用、应用外框、对话主列、
  会话内容区、输入区、输入框、新对话占位文字、工作区会话树，直接从目录里挑）。
  锚点找不到时（例如那页还没挂载）图片不会乱贴，而是保持不动等页面回来；面板会显示 `✓ 已锚定 · <名字>` 或
  `⚠ 当前页面上找不到这个锚点，图片不会显示`，不用再猜"图为什么没了"。改锚点**即时生效**，不必先保存。
- **令牌**面板：按背景 / 边框 / 品牌色 / 文字 / 按钮 / 交互分组，逐项覆盖 `--dsw-*`。
- 工具条可**收起右侧面板**看整页；所有面板、工具条、选中框都是插件自有层，退出即消失。

**保存 / 应用 / 关闭**

| 按钮 | 行为 |
|---|---|
| **保存** | 写入皮肤文档并**留在绘制模式**继续编辑（不改变皮肤的启用状态） |
| **应用** | 写入 + 启用，并**退出绘制模式** |
| **✕ 关闭** | **直接关闭，舍弃未保存的改动**（页面立刻回到皮肤文档的状态；要写入请点「保存」或「应用」）。第二次 Esc 同义 |

### 皮肤包 `.dshskin`

「导出皮肤」产出的是一个**标准 ZIP**（任何解压工具都能打开），把"配置"和"素材"分开存：

| 条目 | 内容 |
|---|---|
| `manifest.json` | 完整配置：令牌、CSS、文字替换、画布（背景/图片）、图层、皮肤库，以及格式版本、生成器、时间戳与资源清单（路径/类型/MIME/字节数） |
| `assets/…` | **原样的图片与字体文件**（不是 base64） |
| `README.txt` | 包内说明 |

- **省体积**：base64 变二进制文件。一份实测主题：351 KB 的 JSON → **141 KB** 的皮肤包（−59.8%）。
- **可换素材**：解开 zip，把 `assets/` 里的图/字体换成同名同格式的文件，重新打包即可导入。
- **兼容**：旧版 `.json` 导出仍可导入；包内资源缺失或损坏会**明确报错**，不会导入半个皮肤。

## 安装（最新版 DSH）

> 给**已经装好并能启动**的 DSH 加一个第三方插件。本插件是 **profile bundle**（包内自带 `cordis.patch.yml`，声明条目 `dsh-myskin`），所以只需要"装进某个 profile + 在它的 `dsh.profile.bundles` 里声明一次"。

### 用 DSH 内置的「添加插件」

打开 **设置 → 插件（Plugins）→ 添加插件**，在输入框里填下面任意一种，选好安装源，点「安装」：

| 输入 | 例子 | 说明 |
|---|---|---|
| GitHub 仓库地址 | `https://github.com/WTStarMark/dsh-myskin` | 走 git 安装；也可写 `github:WTStarMark/dsh-myskin`，需要固定版本就加 `#v0.3.9` |
| npm 包名 | `dsh-myskin` | 走所选**安装源**（`registry.npmmirror.com` = 中国大陆镜像源） |
| 本地目录路径 | `~/dsh-plugins/dsh-myskin-0.3.9` | 等价于 `link:`，改源码即时生效 |

- 「安装源」只影响 npm 包；填 GitHub 地址时走 git，不受它影响。
- 安装由 **pnpm** 执行，机器上需要有 `pnpm`。
- 安装完成后，插件管理器会**自动**把 `dsh-myskin` 写进**当前 profile** 的 `dsh.profile.bundles`——不需要手改配置文件。
- 请注意界面上的提醒：**插件暂不支持自动更新**；升级请先在插件页**卸载**，再安装新版本。
- 只想给桌面端装，就在桌面版里对同一个地址再装一次（Web 与 Desktop 是两个 profile，皮肤文档也各自独立）。

### 装上了吗

1. **设置**里出现 **「皮肤管理」** → 成功。
2. 只用命令行确认宿主半区（把 `<pkg>` 换成实际安装目录）：

   ```bash
   node --input-type=module -e "const m = await import('<pkg>/lib/index.js'); console.log(Object.keys(m))"
   # 期望输出：[ 'Config', 'apply', 'name' ]
   ```

### 让 AI 助手认识这个插件（可选）

插件包里自带一份技能说明 `skills/dsh-myskin/SKILL.md`：讲清皮肤文档的字段与语义、绘制模式的各项契约（选择/组块编辑/字体/锚点/回收站）、
`.dshskin` 的读写格式与可逆性红线。把它注册进 DSH 的技能目录，助手在讨论、编写或排查皮肤时会**自动加载**：

```bash
DSH_HOME="${DSH_HOME:-$HOME/.dsh}"
ln -sfn /path/to/dsh-myskin/skills/dsh-myskin "$DSH_HOME/skills/dsh-myskin"
```

技能是一个**目录包**：`$DSH_HOME/skills/<名字>/SKILL.md`（YAML frontmatter 里写 `name` / `description` / `whenToUse`）。
它由 DSH 的 `skill-filesystem` 提供者扫描并**热监听**，链接建好后**不需要重启**，技能目录下一次刷新即可看到。
不需要了就直接删掉那个软链（只影响助手能不能读到你这份说明，不影响插件本身）。

### 卸载 / 回滚

- 插件页对该插件选「卸载」——它同时会从 `dsh.profile.bundles` 移除条目。卸载后刷新页面（改了 schema 的版本再重启一次 DSH）。
- 皮肤文档仍留在该 profile 的 `cordis.patch.yml` 里；想彻底清干净，先「导出皮肤」备份，再删掉该条目。

## 让 AI 设计你的主题（`/dsh-myskin`）

在对话输入框里敲 **`/dsh-myskin`** 就会开始一次主题设计——宿主插件把一段引导交给助手，助手据此加载随包技能、问清偏好、给出方案并落地。

| 你输入 | 会发生什么 |
|---|---|
| `/dsh-myskin` | 助手**先问你四件事**（明暗偏好 / 主色或氛围 / 字体 / 要不要图），再给 1–2 套方案 |
| `/dsh-myskin 深色 + 青色，界面用等宽字体` | 带着你的方向直接进入方案设计 |
| `/dsh-myskin 做成浅色纸质，正文要衬线` | 同上；方案会写到**令牌级**（背景 / 表面 / 边框 / 文字档位 / 品牌色） |

助手交付时会给你：用了哪些令牌与规则、**对比度怎么算过的**（正文 ≥ 4.5:1 等底线）、怎么一键还原、怎么导出 `.dshskin` 备份。
落地有两条路：**让助手生成一个 `.dshskin`**（你在「皮肤管理 → 导入皮肤」里选它），或给你一张**可粘贴清单**手动填。

> 助手**不会**直接改你的 profile 配置——皮肤文档存在那里，属于只读红线；一切改动都由你在界面里确认。

**前提**：本次升级新增了这个命令（宿主半区），所以**要重启一次 DSH** 才会出现在 `/` 菜单里；
只做样式/预设的升级不需要重启。另外把随包技能注册上（见上一节），助手才知道完整的操作契约。

## 快速上手

1. **设置 →「皮肤管理」**：选一个预设主题 → 点 **应用**。
2. 点 **绘制模式**：在真实页面上点选一个元素，右侧改颜色/字号，或直接在「编辑文字」里改文案（边打边变）。
3. **保存**（继续调）或 **应用**（写入并退出绘制模式）。
4. **导出皮肤**：得到 `.dshskin` 备份，换机器或换 profile 时 **导入皮肤** 即可。

---

## 数据与持久化

- 皮肤文档保存在**该 profile 的** `cordis.patch.yml`（插件条目 `dsh-myskin` 的 `config`）。
- 由于文档跟着 profile 走，**Web 与 Desktop 的皮肤互不共享**——用 `.dshskin` 导出/导入搬运。
- 「皮肤库」可以存多套命名皮肤，随时切换。
- 关掉「启用皮肤」= 页面完全还原（文档仍保留，随时再打开）。

## 常见问题

**Q：启动时报 `dsh-myskin (dsh-myskin): failed to import`？**
这句由 DSH 的启动器在"Loader 没拿到 fiber"时记下，**真实异常被吞掉了**。按顺序排查：

1. 目录名/位置对不对：必须是 `$PROFILE/node_modules/dsh-myskin`，里面能看到 `lib/index.js` 与 `cordis.patch.yml`；
2. 宿主半区能否独立导入：`node --input-type=module -e "await import('<pkg>/lib/index.js')"` —— 能打印 `Config,apply,name` 就没问题（本包的 `lib/index.js` 自带依赖，**解压/拷贝/软链三种装法都不需要 `node_modules`**）；
3. 该 profile 的 `dsh.profile.bundles` 里是否真的写了 `dsh-myskin`；
4. 还不行就重启 DSH（`patchReload: live` 才热更）。

**Q：点「应用」提示保存失败？**
多半是文档太大。壁纸/嵌入图会按最长边自动压缩，但**嵌入字体是原样保存的**：超过 2 MB 就会让每次保存都变慢，太大可能直接被拒绝。建议整站字体用系统字体名，或使用子集化后的 `.woff2`。

**Q：提示「保存失败：canvas」？**
这条说的是**画布字段被宿主拒了**（`css` 一般同时是成功的）。最常见的原因不是你的数据有问题，而是**宿主 schema 比客户端旧**：
装了新版本但**没重启 DSH**。此时客户端已经会写新字段（例如锚点类型 `group`），而运行中的宿主还在用旧 schema 校验，于是**整个 `canvas` 字段**被拒。
两条出路：① **重启 DSH**（重启后刷新页面）——注意**重启会结束当前会话**；② 先不改这一点：把相关图片的锚点从「整组」改回「元素」再保存。
若画布数据确实很大（面板会显示约多少 KB），则是大小问题：换一张更小的图即可。

**Q：装了新版本要重启 DSH 吗？**
**要**，但只对**宿主半区**（`lib/index.js`，负责 schema 与设置落盘）必要；**客户端半区**（`lib/client.js`）在本机是 `patchReload: live`，热更即可。
所以：**只改样式/预设/绘制模式的版本可以只刷新页面；改了字段 schema 的版本必须重启 DSH。**

**Q：预设主题会不会让字看不清？**
不会：三套预设的文字档位都按它实际落在其上的背景算过对比度——
正文/次级 ≥ 4.5:1（WCAG AA）、三级 ≥ 3:1、caption ≥ 2.6、dimmed ≥ 2.2；主按钮与对比按钮的文字与其填充色 ≥ 4.5；
品牌色在主背景上 ≥ 3。这些底线由 `tests/preset-contrast.test.mjs` 钉住，改预设时会直接跑红。
深海 / 暖阳 / 粉黛**都跟随应用的明暗模式**（深色模式一套、浅色模式一套，各自配色完整），所以不会出现“深色界面里一块白底 + 白字”。
想回到原生外观用「默认」或关掉「启用皮肤」。旧版内置的「极夜」（强制两模式都深色）已按需求移除，
但用它的令牌保存过的皮肤照旧生效（皮肤文档存的是令牌值，界面会显示为「自定义皮肤」）。

**Q：点了「本机字体」弹授权 / 列表很短？**
Chromium 内核（Chrome / Edge）用 Local Font Access API 枚举本机字体，首次需要你在浏览器里点一次「允许」；
拒绝后（或 Firefox / Safari 这类没有该接口的浏览器）会自动退化成**候选字体探测**，列表顶部会写明来源。
授权随时可在浏览器「网站设置 → 字体」里改，刷新页面后重新点一次按钮即可。

**Q：改了没效果？**
确认「启用皮肤」是打开的；再看当前是哪个 profile（Web 里改的不会出现在 Desktop）；用「实时预览」先确认改动本身有效。

**Q：绘制模式里设置弹窗位置怪怪的？**
这是有意的：绘制模式下真实页面会内缩，设置弹窗遵守同一条内缩规则，所以它落在应用区里居中，而不是被工具条/面板盖住。

**Q：怎么把皮肤带回原生？**
「皮肤管理 → 还原默认」清空整套皮肤；或关掉「启用皮肤」。两者都不影响 DSH 自身。
